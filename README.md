# Jev 主动回复插件

让 AstrBot 按照自己的角色和聊天语境参与群聊：顺着刚聊过的话题回应，接住有意思的内容，也能在人家聊得好好的时候不插嘴。

Jev 负责快速判断是否值得接话，真正的回复仍由你给 AstrBot 配置的主模型生成。人设、上下文、记忆和图片继续走原有链路，不需要在这里重新配一套。

**作者：木有知 · 版本：0.10.3 · AstrBot 4.26.8+（低于 5.0）· aiocqhttp 群聊与可选私聊**

## 三步开始

1. 在 AstrBot 插件市场或通过仓库地址安装本插件。
2. 打开配置，填写“启用会话”，选择 Jev 服务并填入对应的 API Key。
3. 保存。默认正式工作，参与程度为“自然”，不需要再关闭任何观察模式。

群号填在“启用会话”里；填 `*` 表示全部已开启类型的会话。没有填群或没有配置 Key 时，不会擅自向群里发言。

**已安装 WakePro 或其他主动唤醒插件时，请先停用被替代的主动回复入口，避免多个插件同时抢答。** 本插件可独立工作，不依赖 WakePro。

在 [南北绿豆站](https://hajimi.165201.xyz) 注册并充值，创建 **Jev 分组**的 API 令牌；在插件里选择“南北绿豆站”，填入这枚 Key 即可。

上游官方号池由站点维护，不需要你另外购买、配置或管理 Jev 官方账号。插件不另外设置每分钟请求数或每日次数上限；账户余额和服务商实际可用性仍然有效。

2026-10-03 上架价：**输入 ¥0.05 / 百万 tokens，输出免费**。实际价格以站内 Jev 分组为准。

南北绿豆站由本插件作者运营，这里是自营渠道推荐。你也可以选择官方直连，插件功能不作区别。

### Jev 官方

选择“Jev 官方”，填入官方 `apikey_` Key。支持多枚 Key，自动在可用 Key 间轮询。

**只需要配置所选渠道。** 切换后只显示对应的 Key 配置；另一渠道原有 Key 会保留，不会混用或发往错误的服务。本站 Key 和官方 Key 不可互换。

## 接管点名与私聊

默认沿用 0.9.0：群聊中的普通消息由 Jev 判断，@、昵称和 AstrBot 的 `wake_prefix` 呼叫走正常回复，私聊走原有处理。

- 开启 `takeover_wake_messages` 后，启用会话内的 @、昵称、引用 Bot 和前缀呼叫也先经过 Jev。显式点名和私聊请求保留一次非空回复；通过判断的轮次复用一次原生生成与发送链。
- 开启 `enable_private_chat` 后，把私聊用户号或完整会话标识加入“启用会话”。启用且未列入禁用会话的私聊由 Jev 接管，未选中的会话继续原有回复路径；屏蔽目标、忽略用户和静音规则继续生效。
- AstrBot 已识别的插件命令、内置命令及其别名继续交给原命令处理器，权限仍由 AstrBot 检查。
- 群聊点名和私聊都沿用现有合并窗口、同人相关补充判定、图片附件保护与发送检查。开启接管后，连续点名进入合并流程；已经开始发送的轮次继续完成投递。

## 判断服务

本插件只用 Jev 判断，不用大模型判断。`relay_mode` 是唯一的**判断服务**选择；最终回复仍由 AstrBot 当前会话的主模型生成，继续使用现有人设、记忆、图片和上下文。

| 配置项 | 默认值 | 用途 |
|---|---|---|
| `takeover_wake_messages` | `false` | 接管群聊点名与前缀呼叫 |
| `enable_private_chat` | `false` | 开启私聊判断与合并 |
| `relay_mode` | `nanbei` | `typesafe` Jev 官方；`nanbei` 南北绿豆；`custom` 自定义 Jev 格式中转 |
| `relay.base_url` | 空字符串 | 自定义 Jev 中转的 HTTPS 地址 |
| `relay.api_key` | 空字符串 | 自定义 Jev 中转凭据 |
| `relay.model` | `jev-latest` | 自定义 Jev 中转模型名 |
| `relay.concurrency` | `4` | 自定义中转并发数，取值 1–20 |

自定义中转必须讲 Jev 原生 `systemone` 协议（请求 `model/state/questions`，返回 `answers`），与官方和南北绿豆完全相同；不是 OpenAI `chat/completions`。以下地址等价：

```text
https://relay.example
https://relay.example/v1
https://relay.example/v1/systemone
```

带路径的地址如 `https://relay.example/proxy/v1` 会保留 `/proxy`。地址使用 HTTPS；凭据填在 Key 字段，不放入 URL。地址无效时插件照常加载，`jev状态` 会提示检查地址。

默认只用所选服务。显式开启 `allow_channel_fallback` 后，其余已填好凭据的 Jev 服务作为备用，只在请求发出前选择；同一次调用遇明确拒绝后的再尝试仍由 `retry_explicit_rejection` 控制。日志只记录安全错误分类与 Key 摘要。

从旧版本升级：`relay_mode=jev`（或没有该字段）改用原 `primary_channel` 的值；已移除的 `astrbot`（AstrBot 提供商）和 OpenAI 格式 `custom` 中转改为南北绿豆，并在日志中警告，旧 OpenAI 中转地址和 Key 会被清空（升级前配置文件已自动备份为 `.bak`）。`primary_channel` 合并进 `relay_mode` 后删除。

## 平时只用调这几项

| 设置 | 怎么用 |
|---|---|
| 参与程度 | 安静 / 自然 / 活跃；通常保留“自然” |
| 聊天偏好 | 用一句话微调，例如“多接梗，少说教，回答简短一点” |
| Bot 昵称 | 句首叫到昵称时直接回应；不填也可以 |
| 连续消息合并窗口 | 同一个人分段发消息时合并，按主模型速度调整 |
| 忽略名单 | 不回应指定用户；也可以只在某个群里忽略 |

“更多设置”提供发送前复查、图片处理、聊天节奏和上下文微调。多数情况下不用改，先观察真实聊天，再调整参与程度和聊天偏好。

## 连续发消息，不重复抢答

第一条消息先判断、先生成，**不强制等满合并窗口**。

同一个人在 10 秒内补充相关内容时，插件会合并文字和图片，并取消未发送的旧轮。不同人的消息保持独立；无关的新话题保留已生成的回复。已有配置的合并窗口继续按保存值运行。

显式应答的正文与媒体在本轮输出结束后合并发送一次，多段语音及语音与正文混排以合并转发展示。已开始的平台投递继续等待结果，失败不自动重发。

## 本地过滤与运行统计

“更多设置 → 聊天节奏”可开关 Jev 前本地过滤，并设置同话题冷却秒数（默认 20，0 关闭冷却）。纯表情、贴纸、短回应和刚被判定沉默的重复话题会本地略过；@ 和昵称呼叫直接放行，普通照片继续按图片设置处理。新安装的判断间隔默认为 10 秒，已有值保持原样。

每小时记录判断调用数（含草稿复查）、已投递回复数、判断调用 P95 延迟、失败数及分类。合批取消单独记为 `cancelled`；`outcomes` 汇总沉默、生成派发、模型沉默和替换等结果。各项按小时重置。连续三次传输失败记录 warning，成功调用后重新计数。审计明细保留最近 5000 条，按上海日期、会话和原因累计的 `daily_summary` 长期保留；升级时从旧审计明细回填一次。分数接近实际阈值 ±0.08 时，审计保存触发消息前 50 字，凭据形式的文本会脱敏。

升级加载时，旧顶层设置迁入缺失的高级分组项；已有高级值优先。原配置先生成带日期的备份，随后删除旧键。渠道互备设置维持原有解析方式。

## 图片、人设和记忆

- **人设自动读取**，不用在插件里重新粘贴角色设定。
- **图片先筛选再看**：默认根据配文和聊天语境判断是否值得回应，通过后才交给主模型读取原图，不是群里一发图就调用主模型。
- **允许自然沉默**：主模型读完图片、记忆或工具结果后，仍可决定不说话。
- **上下文优先保留原文**：未接近容量上限时保留原文；接近上限才整理旧消息，不偷偷切掉当前消息和人设。
- **默认保留正常点名**：接管开关关闭时，@、引用 Bot 和昵称呼叫仍走 AstrBot 的正常回复链。

Jev 本身是文字判断模型，不识别图片像素。毫无配文和对话背景的纯图片可能被略过；更希望主模型主动看图时，可以在“更多设置”中修改图片处理方式。

| 命令 | 用途 |
|---|---|
| `jev状态` | 查看当前会话是否启用、所选渠道和最近处理情况 |
| `jev静音 10` | 当前会话暂停主动接话 10 分钟 |
| `jev开口` | 解除当前会话静音 |

## 兼容说明

支持 AstrBot 4.26.8–4.x，已分别在 4.26.8 与 4.28.2 上验证原生事件、配置迁移、附件收集与发送流程。适配 ContextAware，并兼顾分段、TTS、表情、图片与撤回。已有正常点名回复的工具能力不会因主动回复而被替换。

本插件内置 `keep_silent`。如果安装了“算了不说了”等同名沉默工具插件，请停用旧的重复实现，避免同名工具冲突。私聊接管由独立开关控制，默认关闭。

发送保护接入 AstrBot 原生事件、Agent 与平台发送链；第三方插件直接调用独立机器人客户端时由其管理发送。

接管事件上的原生 `bot.send_*` 调用返回 `QueuedDelivery` 入队确认，`status` 初始为 `queued`，不是平台回执。整轮结束后统一发送，成功时 `status=delivered`，`receipt` 保存平台返回值（含 `message_id`）；此时也可用 `get("message_id")` 或索引读取，投递前 `get` 返回 `None`。发送失败为 `failed`，发送前取消为 `cancelled`。依赖消息 ID 的扩展应在整轮结束后读取回执，不要在生成或装饰回调中等待整轮结束。内置 `send_message_to_user` 对当前会话的调用也使用同一发送队列；异会话收件目标和无法合并的原生参数抛出 `DeliveryDeclined`，不会改投当前会话。接管关闭时原生 API 返回行为不变。

## 常见问题

**保存后为什么没接话？**

先发 `jev状态` 检查群范围、所选渠道的 Key 和账户余额。主动回复不是每条必回，判断不值得插话时保持安静是正常行为。

**回复太频繁或太少？**

先调整“参与程度”，再用“聊天偏好”描述你想要的表现。不要同时开启多个主动回复插件。

**多 Key 能增加同一个账号的额度吗？**

不能。多 Key 轮询用于分配请求和避开不可用凭据，同一账户的余额仍然共享。上游返回限流或过载时会临时退避，不会无限重试。

**本站 Key 能用于其他工具吗？**

可以用于支持 **Jev 原生请求**且允许自定义服务地址的工具，不绑定本插件：

| 项目 | 值 |
|---|---|
| 完整接口 | `https://hajimi.165201.xyz/v1/systemone` |
| Base URL（工具自行拼接 `/systemone` 时） | `https://hajimi.165201.xyz/v1` |
| 模型 | `jev-latest` |
| 鉴权 | `Authorization: Bearer 你的南北站Key` |
| 请求字段 | `model`、`state`、`questions` |

支持 `noul`、`choice`、`score` 三类判断。它不是普通聊天接口，不能把 OpenAI 的 `messages` 请求直接当作 Jev 原生请求，也不提供流式聊天或原生看图能力。

**从旧版升级需要重新填 Key 吗？**

从 0.7.x 升级会保留官方和本站 Key、启用群、忽略名单和聊天偏好，改为正式运行并移除旧版额外请求配额。MindsHub 已不再支持；更早版本的旧 Key 不会自动复制到本站。
